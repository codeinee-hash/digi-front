# DiGi GeoPlatform — Картографическая GIS-платформа

Интерактивное веб-приложение для управления геопространственными слоями с суточным таймлайном, аналитикой на Recharts, 3D-объектом связи и защитой от race conditions.

- **Демо онлайн:** [https://digi-front-zeta.vercel.app](https://digi-front-zeta.vercel.app)
- **Репозиторий:** [https://github.com/codeinee-hash/digi-front](https://github.com/codeinee-hash/digi-front)

---

## Ответы на вопросы задания

### 1. Как устроена архитектура приложения

Приложение построено по упрощенной 3-уровневой методологии Feature-Sliced Design (FSD):

- **`app/`**: точка входа, провайдеры контекста (`vedro`, `tooltip`), глобальный макет `AppLayout`.
- **`features/`**:
  - `layer-management/`: нормализованный стор Vedro, хуки действий, список слоев, регулировка прозрачности, тумблер эмуляции сбоев.
  - `timeline/`: временная шкала (`06:00`–`22:00`), автовоспроизведение (Play/Pause), пошаговое переключение, синхронизация.
  - `analytics/`: правый выезжающий `Drawer` с интерактивным графиком **Recharts** (AreaChart), сводными метриками и телеметрией.
  - `map-viewer/`: интерактивный холст карты, рендеринг слоев, анимация частиц ветра 60 FPS, отображение 3D SatCom-станции.
- **`shared/`**: UI Kit (`@base-ui/react`, Tailwind CSS v4), Mock API с `AbortSignal`, `LayerAbortManager`, доменные типы.

В верстке применен паттерн **Slot-based Layout** (`AppLayout`, `TimelineLayout`, `MapViewerLayout`, `LayerListLayout`), разделяющий структуру разметки и бизнес-логику.

### 2. Почему выбрана такая картографическая библиотека

Для визуализации использован высокопроизводительный Canvas 2D контекст с WGS 84 геопривязкой (Бишкек, Чуйский регион: 42.8746° N, 74.5698° E):

- **Полный контроль над кастомным рендерингом**: анимация векторного поля ветра (110 частиц со шлейфом), радиальные тепловые градиенты и инсоляция рассчитываются на уровне пикселей без накладных расходов DOM.
- **3D-моделирование без тяжелых внешних движков**: реализована изометрическая 3D-модель спутникового телепорта DiGi (шестигранный постамент, решетчатая мачта, вращающееся зеркало антенны и импульсный луч к спутнику) прямо на холсте.
- **Архитектурная независимость**: интерфейс слоев и стор изолированы от рендерера; при необходимости интеграция MapLibre GL JS / Deck.gl требует замены только компонента представления.

### 3. Как организовано состояние в Vedro

- Стор нормализован: `layers: Record<string, LayerState>`, `layerIds: string[]`, `selectedTimestamp: string`, `isPlaying: boolean`, `isAnalyticsOpen: boolean`.
- Для подписки используется `useLayersSelector` с атомарными селекторами. Изменение параметров одного слоя (например, прозрачности) не приводит к повторному рендеру соседних карточек слоев или других компонентов.

### 4. Как связаны timeline, данные, карта и Recharts (Двусторонняя синхронизация)

1. **Timeline ➔ Карта и Recharts**: при изменении времени в Vedro store (`selectedTimestamp`) карта синхронно перерисовывает суточный градиент температуры, скорость ветра и солнечную радиацию. В Recharts вертикальный маркер `ReferenceLine` перемещается на выбранную отметку.
2. **Recharts ➔ Timeline и Карта (Двусторонность)**: клик по любой точке графика в правом Drawer вызывает `setSelectedTimestamp(time)`, что мгновенно переключает ползунок времени и состояние слоев карты.

### 5. Где проходит граница между UI, состоянием, работой с данными, картой и аналитикой

- **Данные**: `src/shared/api/mock-layers-api.ts` — сетевой уровень с поддержкой `AbortSignal` и задержек.
- **Отмена и гонки**: `src/shared/lib/abort-manager.ts` — управление отменой через `AbortController` и монотонные `requestId`.
- **Состояние и логика**: `src/features/*/model/` — стор Vedro, экшены и хук `useMapViewer`.
- **UI и визуализация**: `src/features/*/ui/` — чистые презентационные компоненты без прямых сетевых вызовов.

### 6. Какие потенциальные проблемы производительности учитывались

- **Race conditions**: при быстром перемещении ползунка Timeline предыдущие незавершенные запросы немедленно отменяются через `AbortController`, предотвращая мерцание и рассинхронизацию.
- **Частота кадров 60 FPS**: анимация ветра и 3D-объекта работает через `requestAnimationFrame` без вызова React-ререндеров на каждый тик.
- **Разгрузка интерфейса**: аналитика Recharts вынесена в правый `Drawer` (`@base-ui/react`), не загромождая рабочую область карты.

### 7. Как масштабировать решение с 3 до 100+ GIS-слоёв

В проекте реализован переключатель «100+ слоёв»:

- Нормализованная структура хранения по `id` обеспечивает доступ за $O(1)$.
- Добавлен мгновенный поиск и фильтрация по категориям (атмосфера, энергетика, спутники, экология).
- Для промышленной эксплуатации на 100+ слоях: виртуализация списка (`@tanstack/react-virtual`), кэширование тайлов через Web Worker и поддержка формата GeoTIFF / NetCDF.

### 8. Сознательно принятые компромиссы

- Использование mock-генератора с искусственной сетевой задержкой вместо поднятия геосервера (GeoServer / WMS).
- Canvas 2D вместо MapLibre/Three.js для исключения тяжелых сторонних рантаймов и сохранения чистоты сборки.

## 3D-объект на карте (Бонус)

В координатах Бишкека (42.8746° N, 74.5698° E) размещен изометрический объект:

- **3D DiGi SatCom Ground Station**: бетонный постамент с затенением, стальная решетчатая вышка, поворотная параболическая антенна и импульсный канал связи к спутнику.
- **Интерактивность**: при клике на вышку на карте открывается правый Drawer с паспортной телеметрией станции (сигнал 94.2%, спутник KAZSAT-3, канал 1.25 Гбит/с).
