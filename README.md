# DiGi GeoPlatform — Управление картографическими слоями GIS

> **Тестовое задание на позицию Frontend Developer в международную группу компаний DiGi (г. Бишкек).**  
> Проект представляет собой модуль управления геопространственными слоями национальной GIS-платформы, объединяющий интерактивную карту, спутниковые растры, векторные поля и аналитические данные.

---

## 🚀 Демонстрация возможностей

Приложение доступно локально на Vite Dev Server:

```bash
npm install
npm run dev
```

### Реализованный функционал согласно ТЗ:

1. **Базовые слои ТЗ**:
   - 🌡 **Температура поверхности** (`TEMP_SURFACE_2M`) — тепловой растр на высоте 2 м;
   - 💨 **Векторное поле ветра** (`WIND_VECTORS_10M`) — скорость и векторные потоки частиц;
   - ☀️ **Солнечная инсоляция** (`SOLAR_GHI_IRRADIANCE`) — суммарная горизонтальная солнечная радиация (GHI).
2. **Управление каждым слоем**:
   - Включение / выключение с мгновенным откликом;
   - Плавная регулировка прозрачности (**Opacity 0–100%**) через слайдер;
   - Жизненный цикл и статусы: `idle` ➔ `loading` (спиннер) ➔ `success` (с метаданными точек растра) / `error` (ошибка с описанием);
   - Кнопка **«Повторить» (Retry)** при сбое загрузки;
   - Имитация асинхронного REST API через mock со случайной задержкой и сетевым джиттером.
3. **Масштабируемость от 3 до 100+ слоев**:
   - В шапке встроен тумблер: **«3 слоя (ТЗ)»** ⇄ **«100+ слоёв (Стресс-тест)»**;
   - Полнотекстовый поиск по названию и коду слоя;
   - Фильтрация по категориям: _Атмосфера, Энергетика, Спутники, Экология_;
   - Массовые действия: «Включить все» / «Сбросить все».
4. **Интерактивная карта Чуйского региона (г. Бишкек)**:
   - Реализован Canvas-движок карты с географической привязкой к штаб-квартире DiGi в Бишкеке (42.87° N, 74.57° E);
   - Живое наложение активных слоев с учетом установленной прозрачности (`opacity`);
   - Анимированные векторные частицы ветра (Streamlines flow);
   - Инспектор географических координат курсора в реальном времени (WGS 84);
   - Динамическая легенда активных слоев со спектральными градиентами.

## ⚡ Управление состоянием в `vedro` и отсутствие лишних render'ов

Библиотека `vedro` решает ключевую проблему стандартного `React.Context` — каскадные лишние перерендеры дочерних компонентов.

### Как это устроено в проекте:

1. **Нормализованный стейт**:
   ```ts
   interface LayersStoreState {
     layers: Record<string, LayerState> // Хранение слоев по id
     layerIds: string[] // Массив идентификаторов
     searchQuery: string
     selectedCategory: LayerCategory | 'all'
     simulateErrors: boolean
     datasetMode: '3-layers' | '100-layers'
   }
   ```
2. **Гранулярная подписка в `LayerItem`**:
   Каждый компонент слоя подписывается исключительно на свой срез:
   ```tsx
   const layer = useLayersSelector((state) => state.layers[layerId])
   ```
   Внутри `vedro` выполняется пошаговая проверка результата селектора (`JSON.stringify(prev) === JSON.stringify(next)`). При изменении прозрачности слоя «Температура» селекторы слоев «Ветер» и «Инсоляция» возвращают неизменные данные, и **React не производит повторный рендер соседних компонентов**.
3. **Визуальный счетчик рендеров**:
   В каждой карточке слоя выведен счетчик `renders: N`. Если подвигать слайдер прозрачности любого слоя, можно наглядно убедиться, что счетчик увеличивается **только у редактируемого слоя**, а остальные 99 карточек остаются статичными.

## 🛡 Борьба с Race Conditions и асинхронностью

При работе с интерактивными GIS-системами пользователи часто совершают быстрые серии кликов: включение ➔ выключение ➔ повторное включение, либо многократное нажатие Retry. Без надлежащей архитектуры устаревший медленный сетевой ответ перетрет актуальное состояние (Race Condition).

### Инженерное решение:

В модуле [`src/shared/lib/abort-manager.ts`](file:///Users/eldiyar/dev/frontend/test-task-digi/src/shared/lib/abort-manager.ts) реализован `LayerAbortManager`:

1. **Мгновенный Abort при повторном действии**:
   При вызове `toggleLayer(id, true)` или `retryLayer(id)` менеджер проверяет наличие активного сетевого запроса для этого слоя и немедленно вызывает `controller.abort()`.
2. **Монотонный `requestId`**:
   Каждому запуску присваивается инкрементный идентификатор. Даже если промис завершится после отмены, проверка `isLatestRequest(layerId, requestId)` гарантирует, что ответ будет проигнорирован.
3. **Отмена при выключении слоя**:
   Если пользователь выключил тумблер слоя до завершения загрузки, сетевой запрос тут же обрывается, не расходуя трафик и вычислительные ресурсы.
4. **Фильтрация ошибок отмены**:
   Ошибки `AbortError` перехватываются функцией `isAbortError(err)` и не переводят UI в статус `error`.
5. **Тумблер «Имитация сбоев API»**:
   В шапку вынесен переключатель, искусственно генерирующий сетевые сбои (504 Gateway Timeout, 503 Overloaded, 429 Rate Limit), что позволяет мгновенно проверить обработку ошибок и работу кнопки «Повторить».

## 💎 Строгая типизация без `any`

Статусы компонентов спроектированы через **Discriminated Unions**, что исключает невозможные состояния (например, одновременное наличие ошибки и флага `isLoading`):

```ts
export type LayerStatus =
  | { type: 'idle' }
  | { type: 'loading'; startedAt: number }
  | { type: 'success'; loadedAt: number; dataPointsCount: number }
  | { type: 'error'; message: string; canRetry: boolean; failedAt: number }
```

Код полностью проходит валидацию `tsc --noEmit` и `eslint .` без единого предупреждения о типах.

## 🤖 Использование AI-инструментов в разработке

В соответствии с требованиями вакансии DiGi, искусственный интеллект использовался как инструмент исследования, архитектурного проектирования и диагностики:

1. **Исследование неизвестной библиотеки `vedro`**:
   - Библиотека `vedro` для React мало распространена по сравнению с одноименным Python-тест-фреймворком. С помощью AI-исследования и анализа исходного кода пакета на npm/GitLab (`useVedroSelector`, `createVedro`, компаратор `JSON.stringify`) были выявлены нюансы работы мемоизации селекторов и сигнатуры типов.
2. **Диагностика и устранение проблем инициализации**:
   - При попытке выполнить `npx shadcn@latest init` возникла ошибка отсутствия path alias в Vite-шаблоне. AI с помощью Context7 MCP оперативно предоставил точечную конфигурацию алиасов для `tsconfig.json`, `tsconfig.app.json` и `vite.config.ts`, решив проблему за один шаг.
3. **Проектирование модели устойчивости к гонкам состояний**:
   - AI использовался для проектирования архитектуры `LayerAbortManager` с поддержкой `AbortSignal` и `requestId`, гарантирующей изоляцию жизненного цикла запросов при быстрых кликах.
4. **Генерация GIS-данных и доменная проработка**:
   - AI помог сформировать реалистичные геопространственные параметры для Чуйской области (координатная сетка WGS 84, параметры инсоляции GHI в Вт/м², векторное поле ветра и растры температуры), что приблизило тестовое задание к реальным задачам DiGi.
